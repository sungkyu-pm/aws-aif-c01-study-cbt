## 1. 파운데이션 모델(FM) 선정 기준 및 트레이드오프

실제 비즈니스 요구사항에 따라 가장 적합한 모델을 선택하는 것이 핵심 시험 출제 포인트입니다:

| 평가 기준 | 고려 사항 | 권장 모델 선택 가이드 |
| :--- | :--- | :--- |
| **작업 복잡도 및 추론 능력** | 고난도 다단계 논리 추론, 코드 생성, 심층 분석 vs 단순 텍스트 요약, 분류 | • 고난도 작업: 대형 모델 (Claude 3.5 Sonnet / Opus, Llama 3 70B)<br>• 단순 작업: 경량 모델 (Claude 3 Haiku, Amazon Titan Text Express) |
| **응답 지연 시간 (Latency)** | 실시간 대화형 챗봇, 자동완성 vs 비동기 일괄(배치) 문서 분석 | • 초저지연 필요: 경량 소형 모델 (Claude 3 Haiku, Mistral 7B)<br>• 배치 처리: 대형 고성능 모델 |
| **비용 최적화 (Cost)** | 입력/출력 1,000토큰당 비용 통제 | 작업 난이도에 맞는 가장 작은 모델을 선택하는 "Right-Sizing" 원칙 적용 |
| **컨텍스트 윈도우 길이** | 처리해야 할 단일 문서나 대화 히스토리의 크기 | 수백 페이지의 PDF나 코드베이스 전체 분석 시 대규모 컨텍스트 지원 모델 선택 (예: Claude의 200k 토큰) |
| **모달리티 (Modality)** | 텍스트 전용 vs 이미지, 도표, 차트 분석 필요 여부 | 이미지/다이어그램 입력 시 멀티모달(Multimodal) 모델 필수 (예: Claude 3, Titan Multimodal) |

## 2. Amazon Bedrock 생태계 완전 해부

Amazon Bedrock은 인프라 관리 없이 선도적인 파운데이션 모델을 **단일 통합 API**로 제공하는 완전관리형 서버리스 서비스입니다:

```
┌────────────────────────────────────────────────────────────────────────┐
│ Amazon Bedrock                                                         │
│                                                                        │
│ ┌────────────────────────────────────────────────────────────────────┐ │
│ │ 파운데이션 모델 (FMs)                                              │ │
│ │  - Anthropic Claude, Meta Llama, Amazon Titan, Mistral, Cohere 등  │ │
│ └────────────────────────────────────────────────────────────────────┘ │
│                                                                        │
│ ┌─────────────────────────────────┐  ┌───────────────────────────────┐ │
│ │ Bedrock Knowledge Bases         │  │ Bedrock Agents                │ │
│ │  - 완전관리형 RAG 파이프라인    │  │  - 다단계 자율 작업 수행      │ │
│ │  - S3 문서 ➔ Chunking ➔ Vector  │  │  - OpenAPI 스키마 ➔ Lambda 호출│ │
│ └─────────────────────────────────┘  └───────────────────────────────┘ │
│                                                                        │
│ ┌─────────────────────────────────┐  ┌───────────────────────────────┐ │
│ │ Bedrock Guardrails              │  │ Bedrock Model Evaluation      │ │
│ │  - 유해 콘텐츠 필터링, PII 마스킹 │  │  - ROUGE/BLEU 자동 평가      │ │
│ │  - 환각 차단, 프롬프트 인젝션 방어│  │  - 인간 평가자(팀/크라우드) 지원│ │
│ └─────────────────────────────────┘  └───────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
```

### A. Bedrock Knowledge Bases (완전관리형 RAG)
* **특징**: 별도의 복잡한 데이터 파이프라인 개발 없이, Amazon S3에 저장된 사내 문서(PDF, Word, TXT, HTML)를 지정하기만 하면 자동으로 문서를 파싱, 청킹, 임베딩하여 벡터 데이터베이스에 색인.
* **지원 벡터 스토어**: Amazon OpenSearch Serverless, Amazon Aurora PostgreSQL (pgvector), Pinecone, Redis Enterprise.
* **검색 방식**: 하이브리드 검색(의미론적 시맨틱 검색 + 키워드 검색)을 통해 최상의 문맥 정확도 보장.

### B. Bedrock Agents (자율형 AI 에이전트)
* 사용자의 자연어 요청을 분석하여 **다단계 실행 계획(Orchestration)**을 스스로 수립.
* **작업 그룹 (Action Groups)**: 사전 정의된 OpenAPI 스키마를 기반으로 백엔드 **AWS Lambda 함수**를 호출하여 실제 외부 시스템(DB 조회, 예약 처리, 티켓 발급 등)과 상호작용.

### C. Bedrock Guardrails (책임 있는 AI 및 안전 통제)
* 애플리케이션의 사용 사례 및 조직의 윤리 정책에 맞게 안전 경계선을 정의:
  1. **차단 주제 (Denied Topics)**: 금융 조언, 법률 자문 등 금지 영역 설정.
  2. **콘텐츠 필터 (Content Filters)**: 증오 발언, 모욕, 폭력, 성적 콘텐츠 수준별 차단.
  3. **민감 정보 필터 (Sensitive Information Filters)**: 주민번호, 신용카드, 이메일 등 PII(개인식별정보) 자동 차단 또는 마스킹.
  4. **단어 필터 (Word Filters)**: 비속어 및 사용자 정의 금지어 차단.
  5. **맥락적 근거성 검사 (Contextual Grounding Check)**: 응답이 검색된 소스 데이터에 근거하고 있는지 검증하여 **환각(Hallucination) 완벽 차단**.

### D. Bedrock Model Evaluation (모델 평가)
* 비즈니스 유스케이스에 가장 적합한 FM을 객관적으로 비교 및 평가:
  * **자동 평가 (Automatic)**: 정확도, 견고성, 유해성, ROUGE, BLEU 등의 지표를 내장 프롬프트 데이터셋으로 자동 산출.
  * **인간 평가 (Human Evaluation)**: 사내 팀원 또는 AWS 관리형 크라우드 인력을 활용하여 주관적 선호도, 브랜드 어조 적합성 등을 직접 채점.

## 4. Amazon SageMaker 주요 도구 비교

* **Amazon SageMaker JumpStart**:
  * 인기 있는 오픈소스 및 독점 파운데이션 모델(Llama, Falcon, Mistral, Stable Diffusion 등)을 사전 훈련된 상태로 원클릭 배포하고 커스텀 데이터셋으로 파인튜닝할 수 있는 허브.
* **Amazon SageMaker Canvas**:
  * **비즈니스 분석가를 위한 시각적 노코드(No-code) 머신러닝 도구**. 코드 작성 없이 클릭 몇 번으로 정형 데이터 예측(분류/회귀) 모델을 학습시키거나, 준비된 FM을 사용해 텍스트 요약 및 콘텐츠 생성을 테스트할 수 있음.
* **Amazon SageMaker Clarify**:
  * 모델 수명주기 전반에서 데이터셋 및 훈련된 모델의 잠재적 편향(Bias)을 탐지하고, SHAP 가치를 계산하여 모델의 예측 설명가능성(Explainability)을 제공.

## 5. 사전 구축된 AWS AI 턴키 서비스 (Turnkey AI Services)

"최소한의 개발 노력", "머신러닝 전문 지식 불필요" 조건이 주어졌을 때 가장 먼저 선택해야 하는 완전관리형 API:

| 도메인 | 서비스명 | 핵심 기능 |
| :--- | :--- | :--- |
| **컴퓨터 비전** | **Amazon Rekognition** | 이미지 및 비디오에서 객체, 사람, 텍스트, 장면 감지, 안면 분석 및 비교, 부적절한 콘텐츠(성인물/폭력) 검출 |
| **문서/OCR** | **Amazon Textract** | 단순 OCR을 넘어 스캔된 문서에서 텍스트, 필기체, 양식(Form - Key/Value 쌍), 표(Table) 구조를 지능적으로 추출 |
| **자연어 처리 (NLP)** | **Amazon Comprehend** | 텍스트 내 감정 분석(Sentiment), 주요 엔티티 추출, 키프레이즈 감지, 언어 감지, PII 탐지 |
| **음성 인식 (STT)** | **Amazon Transcribe** | 오디오 음성을 텍스트로 자동 변환 (화자 분리, PII 마스킹, 실시간 스트리밍 지원) |
| **음성 합성 (TTS)** | **Amazon Polly** | 텍스트를 자연스러운 인간 음성(오디오)으로 변환 (신경망 음성 NTTS 지원) |
| **기계 번역** | **Amazon Translate** | 수십 개 언어 간의 유창하고 정확한 신경망 기반 기계 번역 지원 |
| **지능형 검색** | **Amazon Kendra** | 기계학습 기반의 엔터프라이즈 자연어 검색 서비스 (FAQ 및 문서에서 직접 답변 추출) |
| **개인화 추천** | **Amazon Personalize** | 실시간 사용자 행동 데이터를 기반으로 제품, 콘텐츠, 맞춤 추천 제공 |

## 6. 생성형 AI 모델 평가 지표 (GenAI Metrics)

| 평가 지표 | 계산 원리 | 주로 쓰이는 태스크 | 특징 및 해석 |
| :--- | :--- | :--- | :--- |
| **ROUGE-1, 2, L** | 생성문과 정답 요약문 간의 **단어(n-gram) 겹침(재현율 Recall 중심)** 계산. ROUGE-L은 최장 공통 부분 수열(LCS) 측정. | **텍스트 요약 (Summarization)** | 0.0~1.0 사이 값으로, 높을수록 정답 요약문의 핵심 정보를 잘 포함하고 있음을 의미. |
| **BLEU** | 생성문과 정답 번역문 간의 **n-gram 정밀도(Precision)** 및 짧은 문장에 대한 브레비티 페널티(Brevity Penalty) 계산. | **기계 번역 (Translation)** | 0.0~1.0 (또는 0~100) 사이 값으로, 높을수록 인간 번역문과 단어가 일치함을 의미. |
| **BERTScore** | 사전 학습된 언어 모델의 **임베딩 벡터 간 코사인 유사도**를 계산. | **다양한 생성형 작업** | 표면적인 단어 일치가 아닌, **의미론적 유사도(Semantic Similarity)**를 평가하므로 동의어나 문장 구조 변경에 강건함. |
| **Perplexity (PPL)** | 언어 모델이 테스트 텍스트의 다음 단어를 예측할 때 느끼는 불확실성(지수화된 교차 엔트로피). | **기초 언어 모델 성능** | **값이 낮을수록** 모델이 텍스트를 유창하고 예측 가능하게 잘 생성함을 의미. |
| **Human Evaluation** | 도메인 전문가 또는 일반인이 일관성, 유용성, 사실성, 톤앤매너를 직접 다면 평가. | **최종 비즈니스 적합성** | 가장 정확하나 시간과 비용이 많이 듦. (RLHF의 핵심 기반) |
