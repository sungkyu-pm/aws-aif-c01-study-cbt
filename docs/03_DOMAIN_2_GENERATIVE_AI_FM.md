## 1. 생성 모델 vs 판별 모델 (Generative vs Discriminative)

* **판별 모델 (Discriminative Model)**:
  * 조건부 확률 $P(Y|X)$를 학습하여 데이터의 경계면을 결정.
  * 주어진 데이터가 어떤 클래스에 속하는지 분류하거나 수치를 예측 (예: "이 이메일이 스팸인가?", "사진 속 동물이 고양이인가?").
* **생성 모델 (Generative Model)**:
  * 결합 확률 분포 $P(X, Y)$ 또는 데이터 자체의 분포 $P(X)$를 학습.
  * 학습한 데이터 분포로부터 **새로운 데이터 샘플을 합성 및 생성** (예: "고양이 그림을 새로 그려라", "고객 불만에 대한 정중한 사과 이메일 초안을 작성하라").

## 2. 파운데이션 모델(FM)과 트랜스포머 아키텍처

### A. 파운데이션 모델 (Foundation Models)의 특징
* 인터넷 규모의 방대한 비레이블 데이터셋(수천억~수조 토큰)으로 **사전 학습(Pre-training)**된 초대형 모델.
* 특정 단일 작업이 아닌 요약, 번역, 질의응답, 코드 생성, 추론 등 다양한 **다운스트림(Downstream) 작업에 범용적으로 활용**.
* **창발적 능력 (Emergent Abilities)**: 모델 크기와 데이터셋이 임계점을 넘어서면서 명시적으로 학습되지 않은 고난도 추론 능력이 자연스럽게 발현되는 현상.

### B. 트랜스포머(Transformer)와 셀프 어텐션(Self-Attention)
* 기존 순환신경망(RNN)의 순차 처리 한계를 극복하고 **병렬 연산(Parallelization)**을 가능하게 한 혁신적 아키텍처.
* **셀프 어텐션 (Self-Attention)**: 문장 내의 모든 단어가 서로에게 미치는 영향력(가중치)을 동시에 계산하여 장거리 문맥 의존성(Long-range dependency)을 완벽히 포착.
* **아키텍처 유형**:
  * **인코더 전용 (Encoder-only)**: 문맥의 깊은 이해 및 분류에 특화 (예: BERT).
  * **디코더 전용 (Decoder-only)**: 다음 토큰의 연속적 자동 생성(Autoregressive)에 특화, 대부분의 현대 LLM (예: GPT 계열, Claude 계열, Llama, Amazon Titan Text).
  * **인코더-디코더 (Encoder-Decoder)**: 번역 및 요약 특화 (예: T5).

## 3. 토큰, 컨텍스트 윈도우 및 추론 하이퍼파라미터

### A. 토큰(Token)과 컨텍스트 윈도우(Context Window)
* **토큰**: 텍스트를 구성하는 기본 서브워드(Sub-word) 단위. (통상 1,000토큰 $\approx$ 영어 약 750단어, 한글은 1~2자당 1~2토큰).
* **컨텍스트 윈도우**: 모델이 한 번의 요청과 응답에서 동시에 기억하고 참조할 수 있는 최대 토큰 용량.
  * 컨텍스트 윈도우가 크면(예: Claude 3의 200k 토큰) 방대한 분량의 책 한 권이나 긴 재무 보고서를 통째로 프롬프트에 넣어 분석 가능.

### B. 추론 하이퍼파라미터 (Inference Parameters)

| 파라미터 명칭 | 역할 및 제어 방식 | 값에 따른 결과 변화 | 권장 사용 사례 |
| :--- | :--- | :--- | :--- |
| **Temperature<br>(온도)** | 다음 토큰 확률 분포의 평탄화 정도를 조절하여 **무작위성/창의성**을 제어. | **낮음 (0.0~0.2)**: 가장 확률 높은 단어만 선택(결정론적, 일관됨).<br>**높음 (0.7~1.0)**: 확률이 낮은 단어도 선택(창의적, 다양함). | • 0.0~0.2: 코딩, 팩트 기반 Q&A, 데이터 추출<br>• 0.7~1.0: 시 창작, 마케팅 문구, 브레인스토밍 |
| **Top-P<br>(Nucleus Sampling)** | 누적 확률이 P(예: 0.9)에 도달할 때까지의 상위 후보 토큰 집합 내에서만 단어를 샘플링. | **낮음 (0.1~0.5)**: 극상위 확률 토큰만 고려(정밀성 향상).<br>**높음 (0.9~1.0)**: 더 넓은 범위의 단어 후보 고려. | Temperature와 함께 조정하여 어휘의 풍부함과 정확성의 균형 유지. |
| **Top-K** | 매 스텝마다 가장 확률이 높은 상위 K개의 단어 후보만 남기고 나머지는 필터링. | **낮음 (예: K=10)**: 엉뚱한 단어 생성 차단.<br>**높음 (예: K=50~250)**: 다양한 표현 허용. | 이상한 단어나 문맥에 맞지 않는 단어 생성을 사전에 억제. |
| **Max Tokens** | 생성할 응답의 최대 길이 제한. | 초과 시 응답이 중간에 끊길 수 있음. | 비용 제어 및 간결한 답변 유도. |
| **Stop Sequences** | 모델이 생성을 즉시 멈추도록 지정하는 특정 문자열 (예: "User:", "\n\n"). | 지정된 단어 출현 시 생성 중단. | 대화형 챗봇에서 턴(Turn) 구분 시 필수. |

## 4. 프롬프트 엔지니어링 5대 핵심 기법 (Prompt Engineering)

모델 가중치를 수정하지 않고, **입력 지시문을 정교화**하여 최적의 응답을 얻어내는 기술:

1. **Zero-shot Prompting (제로샷)**:
   * 사전 예시 없이 작업 지시문만 직접 제공.
   * *예시*: "다음 고객 피드백의 감정을 긍정 또는 부정으로 분류해: '배송이 하루 만에 도착했어요!'"
2. **Few-shot Prompting (퓨샷)**:
   * 원하는 입-출력 형식의 모범 예시(1~5개)를 프롬프트 내에 포함시켜 원하는 어조나 포맷(JSON 등)을 명확히 유도.
   * *예시*:
     ```text
     Review: "화면이 너무 어둡습니다." -> Sentiment: 부정
     Review: "가성비 최고입니다!" -> Sentiment: 긍정
     Review: "디자인은 예쁜데 무거워요." -> Sentiment:
     ```
3. **Chain-of-Thought (CoT, 생각의 사슬)**:
   * 복잡한 논리 추론, 계산 문제를 풀 때 **"단계별로 생각하라(Let's think step by step)"**고 유도하여 중간 추론 과정을 명시하게 함으로써 오류를 극적으로 감소시킴.
4. **Directional Stimulus Prompting (방향성 자극)**:
   * 힌트나 특정 키워드를 프롬프트에 주입하여 모델이 특정 방향으로 요약하거나 결론을 내리도록 유도.
5. **System Prompt & Role Prompting (시스템 프롬프트 & 역할 부여)**:
   * "너는 20년 경력의 금융 컴플라이언스 전문가다. 초보자도 알기 쉽게 설명하되 법적 위험은 엄격히 경고하라."와 같이 역할, 제약 조건, 거부 규칙을 사전 정의.

## 5. 모델 커스터마이징 스펙트럼 (Customization Options)

```
[비용/복잡도 낮음] ─────────────────────────────────────────── [비용/복잡도 높음]
Prompt Engineering  ➔  RAG (검색 증강)  ➔  Fine-Tuning (PEFT)  ➔  Pre-training
(가중치 수정 X)        (외부 지식 검색)       (도메인 특화 가중치 조정)    (기초 모델 처음부터 학습)
```

| 기법 | 모델 가중치 변경 여부 | 추가 데이터 요구량 | 적합한 사용 목적 / 특징 |
| :--- | :---: | :---: | :--- |
| **Prompt Engineering** | **없음 (No)** | 0개 (지시문만) | 가장 빠르고 저렴함. 단순 포맷팅, 요약, 기본 Q&A. |
| **RAG (Retrieval-Augmented Generation)** | **없음 (No)** | 비정형 문서 (PDF, FAQ 등) | **최신 데이터, 사내 기밀 문서, 빈번히 업데이트되는 지식**을 모델에 주입하고 출처(Citation)를 명확히 해야 할 때 최적. |
| **Fine-Tuning (전체 파인튜닝)** | **전체 변경 (Yes)** | 수만~수십만 개의 레이블 데이터 | 특정 산업 전문 용어, 독특한 어조/문체, 복잡한 태스크를 영구 체화. 비용/GPU 연산 높음. |
| **PEFT / LoRA (매개변수 효율적)** | **소형 어댑터만 변경 (Partial)** | 수백~수천 개의 전문 데이터 | 기본 가중치는 고정(Freeze)하고 **소형 저차원 어댑터만 학습**하여 컴퓨팅 비용 90% 절감. |
| **Pre-training from Scratch** | **전체 신규 생성** | 수조 토큰의 초대형 데이터셋 | 자체 기반 모델 제작. 수백만 달러 이상의 컴퓨팅 비용 필요. 극히 예외적. |

## 6. RAG (Retrieval-Augmented Generation) 아키텍처 상세

```
[사용자 질문] ──────────────────────────────────────────────┐
     │                                                      │
     ▼ (1. 텍스트 임베딩)                                    ▼
[질문 임베딩 벡터]                                    [컨텍스트 결합 프롬프트]
     │ (2. 코사인 유사도 k-NN 검색)                         │ (4. FM에 주입)
     ▼                                                      ▼
[벡터 데이터베이스] ──(3. 최상위 관련 청크 검색)───> [Amazon Bedrock FM] ──> [정확한 답변]
 (OpenSearch Serverless / Aurora pgvector)
     ▲
     │ (오프라인 수집 파이프라인: 문서 로드 ➔ Chunking ➔ Embedding)
[사내 지식 저장소 (Amazon S3)]
```

1. **문서 청킹 (Chunking)**:
   * 긴 문서를 의미 단위 또는 일정한 토큰 크기(예: 300~500 토큰)로 분할. 검색 적중률과 문맥 보존의 균형을 위해 오버랩(Overlap, 예: 10~20%)을 적용.
2. **벡터 임베딩 (Vector Embeddings)**:
   * 텍스트 청크를 다차원 실수 벡터(예: 1536차원)로 변환하여 의미적 유사도를 수치화 (예: Amazon Titan Text Embeddings).
3. **유사도 검색 (Similarity Search)**:
   * 질문 벡터와 문서 벡터 간의 **코사인 유사도(Cosine Similarity)** 또는 내적(Dot Product)을 계산하여 가장 연관성 높은 상위 k개의 청크 추출.
4. **증강 및 생성 (Augment & Generate)**:
   * 추출된 원본 청크 텍스트를 시스템 프롬프트에 컨텍스트로 주입하고, 파운데이션 모델이 해당 사실에 기반해서만 답변을 작성하도록 강제.

## 7. 환각 (Hallucination) 완화 전략

* **환각 현상**: LLM이 사실에 기반하지 않은 거짓 정보나 지어낸 허구를 사실인 것처럼 그럴듯하게 출력하는 현상.
* **시험 출제 완화 해결책**:
  1. **RAG 도입**: 답변의 근거가 되는 검증된 사내 지식(Ground Truth)을 프롬프트 컨텍스트로 제공.
  2. **Temperature 낮추기**: 0.0~0.2로 설정하여 모델의 결정론적/사실적 출력 유도.
  3. **명시적 지침(System Prompt)**: "제공된 문서에 정보가 없는 경우 절대로 지어내지 말고 '제공된 문서에서 확인할 수 없습니다'라고 답변하라"고 지시.
  4. **Amazon Bedrock Guardrails 적용**: 사실성 검증(Contextual Grounding Check) 및 환각 필터 활성화.
  5. **출처 인용(Citation) 요구**: 모델이 답변을 생성할 때 참조한 문서의 원문 문장이나 페이지 번호를 함께 명시하도록 강제.
